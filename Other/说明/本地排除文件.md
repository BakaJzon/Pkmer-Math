本指南用于在本地工作区中排除远程仓库的特定目录，而不影响远程仓库本身。

## 1.  **进入仓库根目录**
    打开终端或命令行，`cd` 到你的本地 Git 仓库根目录。
## 2. **启用 Sparse Checkout**
```bash
git sparse-checkout init --cone
```
## 3. 使用 non-cone 模式
执行以下命令来初始化稀疏检出功能。

```bash
git sparse-checkout init --no-cone
```
此命令会初始化功能并明确告知 Git 使用 non-cone 模式。这种模式允许我们使用通配符 (*) 和排除符号 (!)
## 4. **设置排除规则**
```bash
git sparse-checkout set /* !'Other/数学分类/'
```
这条命令的作用是：同步所有根目录下的文件和文件夹，但是排除 "Other/数学分类".
**注意**: 执行后，Git 会**立即**从你的本地工作区移除这些目录。

你也可以使用空格分隔, 输入多个目录
```bash
git sparse-checkout set /* !'assets/' !'Other/'
```

## 5. 后续工作流
  * **工作流不变**: 日常 `git pull`, `git push`, `git commit` 等操作**完全照常**，无需任何额外步骤。
  * **恢复显示**: 如果某天你又需要那个目录了，只需重新应用规则，把它从排除列表中去掉即可。要恢复所有文件，可执行：
    ```bash
    git sparse-checkout reapply
    ```

## 6. 稀疏提交

如果你想让本地只保留需要的数学内容，不把前端、部署或其他配置文件拉到你的本地磁盘里, 可以用这个方案. 
这个方案只影响本地显示，不影响远端仓库，也不影响别人正常使用。
操作流程：

1. 克隆仓库后，在仓库根目录启用 `sparse-checkout`。
2. 按自己的需要写排除规则，只保留常用目录。
3. 后续 `pull / commit / push` 照常使用，不需要额外步骤。

如果只是本地不想下载某些目录, 比如GitHub Action部署相关的`static.yml`，可以直接用这套方法；

```bash
git show origin/main:.github/workflows/static.yml
```

如果临时需要查看远端的部署配置，也不必恢复全部文件，可以直接读取远端内容，例如：
```bash
git ls-tree -r --name-only origin/main .github/workflows
```

## 7. 可选策略：对本地配置使用 `merge=ours`

如果某些文件你希望保留自己的本地版本，不想在合并时反复处理冲突，可以给这类文件单独加一个合并策略。
这个做法适合 `.obsidian/` 这种本地界面、工作区状态、插件配置之类的文件；不适合需要多人认真同步的公共配置。

例如：

```gitattributes
.obsidian/** merge=ours
```

如果本机还没有配置 `ours` 驱动，可以执行：

```bash
git config --global merge.ours.driver true
```

配置后，`.obsidian/` 下的文件在发生 merge、rebase、cherry-pick 冲突时，会优先保留你当前分支的版本。

这个策略的特点是：

1. 平时 `pull / commit / push` 不受影响。
2. 只有在合并冲突时才会生效。
3. 可以减少本地配置文件的冲突。
4. 也意味着别人在这些文件上的改动，合并时可能不会进入你的当前分支。

所以，这个策略建议只用于本地配置文件，不要用于需要协作维护的正文、脚本或工作流文件。
